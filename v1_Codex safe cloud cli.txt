	•	Codex Cloud Security Hardening Guide

	•	This guide ensures your Codex Cloud environment runs entirely private and device-only, with no external access unless you explicitly allow it.

1. Configuration

	•	1.1 Disable External Access
	•	
Edit ~/.codex/config.toml:

[cloud]
	•	# Disable all external submissions
enabled = false

# Prevent automatic uploads or syncs
auto_sync = false

# Disable telemetry and background calls
telemetry = false

Launch Codex in offline mode:

codex --offline --sandbox read-only --no-cloud

	•	This ensures no cloud or network activity occurs without your approval.
	•	
	•	---
	•	
	•	1.2 Enforce Local-Only Execution
	•	
	⁃	Restrict Codex to local directories only:
	•	
	•	codex --cd ~/Projects --add-dir ~/PrivateData
	•	
	⁃	Whitelist allowed commands in config.toml:

[permissions]
allowed_commands = ["ls", "cat", "python"]

Any command outside this list will require manual approval.

1.3 Approval Modes

Use /permissions in the CLI and select Read-only or Auto (offline):

	⁃	Read-only – Codex analyzes but does not modify files.
	⁃	Auto (offline) – Codex can modify only local files; never contacts the network.

Conducting Local Code Reviews

Initiate a local code review by typing /review in the command line interface (CLI). This action opens Codex’s review presets, which launch a dedicated reviewer responsible for analyzing the selected diff and reporting prioritized, actionable findings without modifying your working tree. By default, the reviewer utilizes the current session model; however, you can override this setting by specifying the review_model in the config.toml file.
	⁃	Reviewing against a base branch allows you to select a local branch. Codex subsequently determines the merge base against its upstream repository, compares your work with the merge base, and highlights the most significant risks before you submit a pull request.
	⁃	Reviewing uncommitted changes enables you to inspect all staged, unstaged, or untracked changes, enabling you to address issues before committing.
	⁃	Reviewing a commit lists recent commits and instructs Codex to analyze the specific change set corresponding to the SHA value you select.
	⁃	Custom review instructions allow you to provide your own wording (for instance, “Prioritize accessibility regressions”) and instruct the reviewer to utilize the same prompt.
Each review session is recorded as an individual entry in the transcript, facilitating the rerunning of reviews as the code evolves and enabling the comparison of feedback.
Web Search

Codex comes with a built-in web search tool. For local tasks within the Codex CLI, Codex enables web search by default and retrieves results from a web search cache. The cache is an OpenAI-maintained index of web results, so cached mode returns pre-indexed results instead of fetching live pages. This reduces the risk of prompt injection from arbitrary live content, but it is still advisable to treat web results as untrusted. If you are using the —yolo or another full access sandbox setting, web search defaults to live results. To retrieve the most recent data, pass the —search flag for a single run or set the web_ flag.search = "“live” in Config basics. You can also set web_search = "To disable Codex, simply type “disabled” in the command line.
Whenever Codex performs a web search, you will observe web_search items appearing in the transcript or codex exec —json output.

Approval Modes

Approval modes determine the extent to which Codex can operate without requiring confirmation. Utilize /permissions within an interactive session to switch modes as your comfort level evolves.
	⁃	Auto (default) permits Codex to read files, edit, and execute commands within the working directory. It still prompts for confirmation before modifying anything outside that scope or utilizing the network.
	⁃	Read-only restricts Codex to a consultative mode. It can traverse files but will refrain from making modifications or executing commands until you approve a plan.
	⁃	Full Access grants Codex the capability to operate across your machine, including network access, without seeking confirmation. Employ this mode judiciously and only when you have confidence in the repository and task.
Codex consistently provides a transcript of its actions, enabling you to review or revert changes using your customary Git workflow.
